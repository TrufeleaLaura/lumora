# Implementation Plan — iOS Photo Editor

_Created: 2026-10-12 · Companion to [RESEARCH.md](RESEARCH.md)_

## 0. Decisions so far
| Topic | Decision |
|---|---|
| Platform / stack | Native iOS: Swift 5 mode, SwiftUI UI, Core Image + Metal render engine, Vision + Core ML for AI |
| Dev machine | Windows only → Xcode project generated by **XcodeGen**, compiled on **GitHub Actions macOS** runners |
| App name | **Lumora** (bundle ID `app.lumora.editor`), English UI (strings kept localizable) |
| Repo | **Public** GitHub repository → unlimited free macOS build minutes |
| Install on iPhone | Unsigned `.ipa` from CI → **Sideloadly** + free Apple ID (7-day re-sign) |
| Test device | iPhone 15 or newer (full AI feature set, generous memory) |
| Minimum iOS | iOS 17.0 (needed by the Core ML models; covers iPhone XS/XR and newer) |
| AI | 100 % on-device (no servers, no running costs). Large models download on first use, not bundled |
| Third-party code | Minimal: ZIPFoundation (unzip downloaded models). Everything else is Apple frameworks + our code |

## 1. Architecture

```

├─ project.yml                  XcodeGen spec (targets, settings, build rules)
├─ App/                         SwiftUI app target

│  ├─ Library/                  photo picker, projects grid, feed planner

│  ├─ Export/

├─ Engine/ (framework)          Core Image + Metal kernels (*.ci.metal), render pipeline, ML services
│  ├─ Pipeline/                 ImageSource (RAW/HEIC/HDR), RenderPipeline, proxy/full-res, caches
│  ├─ Filters/                  tone, color, detail, effects, looks, beauty, body, overlays
│  ├─ Kernels/                  Metal Core Image kernels
│  ├─ Warp/                     displacement-field builder (liquify, face, body)

│                               Segmenter, Inpainter (LaMa), Upscaler, DepthEstimator

├─ .github/workflows/ios.yml    build + test + package .ipa + upload artifacts
├─ scripts/                     packaging, artifact download helpers
└─ docs/
```

### Non-destructive edit model
`EditDocument` (Codable value type) = source reference + ordered, typed settings:
`geometry` · `retouchOps` (heal/clone/remove) · `warps` (face, body, liquify strokes) · `beauty` (per detected face) ·
`body` · `global` (light/color/effects/detail) · `masks` [mask definition + its own adjustment set] · `look`
(preset + LUT + strength) · `overlays/frames/text`. Undo/redo = snapshots of the document (coalesced per slider drag).
Presets = partial documents (so "copy/paste settings" and "save preset" are the same mechanism).

### Render pipeline (Core Image graph, float16 linear wide-gamut)
1. Decode (CIRAWFilter for RAW; HDR gain-map aware for HEIC) → orientation → working space
2. Retouch results (cached patches) → 3. Displacement warp (face + body + liquify, one pass)
4. Beauty (skin, eyes, teeth, brows, makeup, hair) → 5. Global tone & color → 6. Local masks
7. Detail (sharpen, NR) → 8. Effects & looks (LUT, grain, glow, overlays) → 9. Crop/straighten/perspective
10. Frames, text, stickers.
Preview renders a screen-sized proxy at 60 fps on a Metal canvas; export re-renders at full resolution.
ML analysis (faces, pose, masks, depth) runs once per photo on a ~1.5 MP copy, results cached and refined.

## 3. How I verify work without a Mac
1. **Compile + unit tests on every push** (iOS simulator on the cloud Mac).
2. **Render tests**: each tool is applied to fixture photos (portrait, full body, landscape) and CI uploads
   before/after **contact sheets**; I download and inspect them myself to judge quality and tune parameters.
3. **UI screenshot tests**: a scripted walkthrough of the app captures screenshots I review for layout bugs.
4. **Your device check at the end of each phase**: install the `.ipa` with Sideloadly, try it, tell me what feels off.

## 4. Build minutes budget
The repository is public, so GitHub-hosted macOS minutes are free and unmetered. If it is ever made private
again: ~200 free macOS minutes/month (≈20–30 runs), Codemagic adds 500 free minutes, then ≈ $0.50 per extra run.
Because the code is public: no secrets, keys or personal data are ever committed.

## 5. Risks & mitigations
| Risk | Mitigation |
|---|---|
| Writing Swift without a local compiler → more compile errors | Small focused commits, strict module boundaries, CI error logs read automatically, no exotic language features |
| Memory limits with 48 MP photos + ML models | Proxy rendering, tiled processing, models loaded on demand and released, analysis at reduced resolution |
| Body/face warps looking fake | MLS rigid warps, person-limited warps + background fill, conservative slider ranges, render-test review |
| Free Apple ID limits (7 days, 3 apps) | Stable bundle ID, Sideloadly auto-refresh; optional upgrade to $99 program later |
| Model download size (~400 MB if all used) | Download per feature on first use, show progress, allow deleting in Settings |
| Model licences | Only MIT/Apache/BSD models in the default build; others listed separately |
